GAME JAM / 2024.07

빛을 향해서

5일의 일정, 기능보다 완성도를 선택하다.

‘변신’을 주제로 만든 2D 퍼즐 게임입니다. 프로그래머 2명과 아트 1명이 5일간 대면 개발했고, PD 겸 프로그래머로 참여했습니다.

팀 규모
3인 · 5일 대면 개발
역할 / 기술
PD · 프로그래머 / Unity · Live2D
결과
청강대 × 유니티 게임잼 우수상
수상▶플레이 영상 보기 ↗

유튜브 썸네일을 누르면 실제 영상을 볼 수 있습니다.

01 / SCOPE

이틀째, 전부 만들 수 없다고 판단했습니다

남은 시간 안에 계획한 기능을 모두 만들기 어렵다고 판단했습니다. 핵심인 변신 시스템과 기초 스테이지를 먼저 끝내는 MVP로 범위를 좁혔습니다.

반드시 남길 것

상황에 따라 능력이 바뀌는 변신과 이를 사용하는 기초 스테이지. 검사로 장애물을 돌파하거나 악사로 음악 기믹을 푸는 식으로 주제를 플레이 규칙에 연결했습니다.

시간을 더 쓰지 않을 것

MVP 이후에는 새로운 기능 추가를 멈추고 이펙트·카메라·Live2D·사운드 연출에 시간을 배정했습니다. 기능 수보다 한 번의 플레이가 매끄럽게 이어지는 데 집중했습니다.

02 / FIVE-DAY PLAN

3일은 핵심 구현, 2일은 폴리싱

DAY 1—3변신 시스템 · 기초 스테이지 · MVP
DAY 4—5이펙트 · 카메라 · Live2D · 사운드

앞부분에 플레이 가능한 핵심을 만들고 뒷부분에 완성도를 다듬는 흐름을 잡았습니다. 단순히 개발을 빨리 마치는 것이 아니라, 마지막 날까지 새 기능을 붙이는 상황을 피하려는 선택이었습니다.

위 흐름은 본인 회고를 바탕으로 재구성한 요약이며, 당시의 원본 일별 일정표는 아닙니다. 이름이 확인되지 않은 제외 기능을 새로 만들어 기재하지 않았습니다.

03 / TEAM & IMPLEMENTATION

작은 팀일수록, 작업 경계를 분명하게

프로그래머는 시스템 구현과 스테이지·기믹으로 파트를 나누고, 아트는 변신 애니메이션과 배경에 집중하도록 작업 범위를 정했습니다. 한 사람이 막힐 때 전체 작업이 함께 멈추지 않도록 역할을 나누려 했습니다.

제가 직접 구현한 부분

변신 시스템

스탯·스킬셋·애니메이션 컨트롤러를 실시간으로 교체했습니다. 형태마다 다른 액션을 처리할 수 있도록 상태 머신 구조를 설계했습니다.

Live2D 연동

Unity에 Live2D SDK를 연동하고, 툴의 IK 제약과 스크립트를 연결해 시선이 마우스를 따라가는 Look-At 동작을 구현했습니다.

팀의 결과물 전체와 제 구현을 구분해 설명합니다. 스테이지·아트·연출의 완성은 다른 팀원과 함께 만든 결과입니다.

04 / RESULT

12개 팀 중 우수상, 그리고 남은 판단 기준

5일 대면 개발을 마쳤고 청강대 × 유니티 게임잼에서 우수상을 받았습니다. 상장 수여일은 2024년 8월 7일입니다.

이 경험에서 가져갈 기준은 ‘하나를 더 넣을 수 있나’보다 ‘핵심 플레이를 더 매끄럽게 만들 수 있나’를 먼저 묻는 것입니다. 범위와 폴리싱 시간을 함께 정한 경험을 보여주는 사례로 남겼습니다.

수상은 확인 가능한 결과이며, 특정 결정 하나가 수상을 만들었다고 단정하지 않습니다. 개발 과정과 본인 기여는 기존 회고를 근거로 정리했습니다.
